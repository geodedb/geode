The control test **could not produce comparable numbers**. Two failures
prevented the loadtest from generating any usable per-level data:

1. **`ping` scenario auth-failed at every concurrency level (c=1..32).** Every
   level recorded `total_queries=0` with `error_samples=["ping: geode: AUTH:
   Authentication failed"]`. The DSN used was
   `localhost:3141?insecure=true&user=geode&pass=<auto-generated 32-char hex>`
   where the password is the value the server wrote to `./.geode_admin_password`
   on first boot (the auto-generated bootstrap password — `GEODE_ADMIN_PASSWORD`
   env was not honored because the data dir already had auth records on the
   second start). Username `geode` is the correct default per
   `src/cli/main.zig:290`. Root cause of the auth rejection is **unresolved**
   for this run; it may interact with the second failure below.

2. **The geode server crashed during/after the `ping` run.** A General
   Protection Exception fired in the QUIC stream-acceptor thread, after a
   burst of `processInitial: sendHandshakePackets failed: NoHandshakeKeys`
   transport errors. Stack:

   ```
   General protection exception (no address available)
     std/atomic.zig:21:40 in load
     src/server/quic_connection_handler.zig:1599:23 in runStreamAcceptorLoop
     src/transport/thread_pool.zig:333:32 in runSubmittedTask
     ... (worker entry frames)
   ```

   After the crash, all subsequent scenarios (`point_read`, `one_hop`,
   `two_hop`, `fan_out`) failed at the data-setup phase with `transport dial
   to localhost:3141: timeout: no recent network activity` — confirming the
   server process had exited (verified post-run: `ps -p 1366640` returns no
   rows; `lsof -i :3141` is empty).

3. **`make loadtest-compare` therefore exits 1**, with output:

   ```
   WARNING: no levels found in ../geode-test-harness/reports/loadtest_ping.json, skipping
   ERROR: no results from any current file
   ```

   (per `benchmarks/loadtest/compare.py:73-80`, the script skips any level
   whose latency strings are empty — which is the case for every level in
   the ping report, because no successful queries ran.)

## Interpretation

The original framing of this control test — "is the QUIC transport healthy
under sustained 16-way load with simple queries?" — cannot be answered as a
PASS/REGRESS verdict against the baseline. **However, the failure mode is
itself informative for the cascade investigation:**

- The crash site is in `quic_connection_handler.zig` `runStreamAcceptorLoop`
  — exactly the QUIC layer the broader investigation is targeting. The
  immediate trigger appears to be QUIC handshake-key handling
  (`NoHandshakeKeys` errors precede the GPA), which is consistent with churn
  in connection / acceptor lifecycle rather than with steady-state ingest.
- The Go loadtest opens fresh connections for each concurrency level
  (sweep across c=1,2,4,8,16,32 with `database/sql` pool), so it exercises a
  connection-establishment-and-teardown pattern very different from
  `msft-graph` ingest's long-lived pinned-connection pattern. Both patterns
  appear to interact badly with the same QUIC subsystem, but in different
  failure modes (cascade vs crash).
- The original "is the cascade msft-graph-specific or general?" question
  remains **unanswered by this test alone**. What is now demonstrated is
  that a separate, possibly related, server-side bug exists in the QUIC
  acceptor lifecycle that prevents the loadtest from acting as a clean
  control. Phase 4's bisection should weigh this in: the QUIC dep bump to
  `c7808ed` and the `processInitial: sendHandshakePackets` code path are
  both worth eyeballing alongside the cascade-specific hypothesis space.
- A targeted re-run of the control test with a **simplified loadtest** that
  opens one long-lived connection per worker and never closes it (matching
  the msft-graph pattern more closely) would isolate the variable. This is
  out of scope for Task 1 but should be considered as a follow-up before
  Phase 4 bisection.

## Verdict

**INDETERMINATE — server crash during control test prevented baseline
comparison; the crash itself is QUIC-layer signal that should be treated as
an additional finding for the broader investigation, not a substitute for
the missing PASS/REGRESS data.**
