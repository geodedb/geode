GAP-0816 — FOLLOW-UP (reviewer Critical) — cancel-id poisoning fixed. The original CancelRegistry was never cleared when a request was answered, so in this synchronous server — where a `$/cancelRequest` almost always arrives AFTER its target was already answered (the COMMON case) — a late cancel for id N was recorded and then wrongly fired a -32800 against the NEXT request that reused id N (editors recycle small integer ids).
