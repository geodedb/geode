> **Format note:** This is a *roadmap* (sequencing + clusters + effort + risk), not a TDD step-by-step. The 21 bugs span 11 independent subsystems and require ~150–300 engineering hours total. Each cluster below gets its **own** detailed per-bug plan (written via `superpowers:writing-plans`) at execution time. This roadmap is the orchestration layer.

> **For agentic workers:** REQUIRED SUB-SKILL: When you pick a cluster to execute, write a fresh per-cluster plan in proper writing-plans format (bite-sized TDD steps, complete code, exact paths), then execute via `superpowers:subagent-driven-development`. Do **not** try to execute this roadmap directly — it's intentionally not in step-by-step form.

**Goal:** Close all 21 bugs filed as GitLab issues #826–#846 (surfaced by `geode-test-harness` specs GAP-0280..GAP-0345).

**Architecture:** Cluster bugs by subsystem so each cluster's fix is an atomic, reviewable change with shared test surface. Execute clusters in priority order: silent-corruption first, then critical security, then high security, then operability, then UX. Defer unbounded-scope clusters (Kafka, Webhook, MV surface) to dedicated design discussions.

**Tech Stack:** Zig 0.16.0+ (core), geode-test-harness YAML specs (integration), GitLab CI, OTel for cross-layer debugging.

## Sequencing principles

1. **Silent-corruption first.** Bugs that produce wrong-but-accepted behavior (#828 audit-noise, #830 silent-commit) erode trust in every other test result. Fix these before relying on the test harness as ground truth for any other fix.
2. **Tests that block follow-up specs second.** Bugs #831 (`tests: []` blocked) and #832 (ABAC unreachable) unblock entire spec scenarios that can then exercise other code paths.
3. **Shared-surface clusters together.** #826/#827/#834/#835 all touch `auth_graph_manager`. Doing them one at a time risks N rounds of regression on the same file. Cluster D treats them as a single chain-seal review pass with shared regression suite.
4. **Defer unbounded scope.** #841 (Kafka client), #842 (Webhook client), #846 (MV GQL surface) are not bug fixes — they are feature implementations. Do not bundle them into a "bug fix loop"; route through product/architecture review first.
5. **Product decisions before code.** #845 (auto-index read-trigger): clarify intent with maintainers before writing a fix. If it's by design, the work is documentation, not code.

## Test harness contract (applies to every cluster)

Every cluster must:

1. **Add or flip a failing harness spec** in `../geode-test-harness/geodetestlab-cli/specs/` before writing fix code. The spec is the failing test for the bug.
2. **Run the full RBAC/AuthN/RLS/TXN suite** (whichever the cluster touches) before and after the fix to catch regressions.
3. **Run with OTel enabled** for any cross-layer cluster (C, D, E, F). Use `make test-everything-otel` from `../geode-test-harness`. Attach `reports/spans.jsonl` to the cluster PR.
4. **Update CANARY tokens** from `BUG_CONFIRMED` / `BUG_PINNED` / `STATUS=BUG_DETECTED` → `TESTED` on close.
5. **Cross-link the closing commit** in the GitLab issue (`Closes #NNN`) and in any related closed issue cited in the bug body.

## Execution policy for this multi-session goal

The user's goal is "fix all bugs in the list." That goal is multi-session by nature. To preserve context across sessions:

1. **This roadmap is the persistent source of truth.** Update it as clusters close.
2. **Each cluster gets a per-cluster plan file** at execution time, following the naming convention above.
3. **Memory writes:** After each cluster closes, save a `project` memory noting `cluster <X> closed YYYY-MM-DD, commits <sha-list>, residuals <if any>`.
4. **PR-per-cluster** (not per-bug). Each cluster ships as one MR with `Closes #N, #M, …` for every bug it resolves.
