# Geode v0.18.0 Release Notes

## Executive Summary

Geode v0.18.0 closes critical gaps identified in v0.17.0, delivering **distributed query federation**, **S3 cloud backups**, **CDC webhook hardening**, and **CBO calibration for small datasets**. All features are runtime-gated with zero compile-time feature switches.

## Major Features

### 1. Distributed Query Federation (Read Path)

**Status**: ✅ IMPLEMENTED | Always enabled (legacy GEODE_ENABLE_FEDERATION flag removed)

#### Implementation

- **Coordinator-Worker Architecture**: Scatter-gather pattern with global merge operations
- **Global ORDER BY**: Deterministic pagination across shards with stable sort keys
- **Distributed Top-K**: Per-shard top-K with final merge for exact results
- **EXPLAIN Support**: Shows distributed plan tree with per-shard operations

#### Key Components

- `src/distributed/query_coordinator.zig`: Main coordinator logic
- `src/distributed/federation.zig`: Federation configuration and connection management
- Transport: QUIC/TLS for shard communication (port 8443)

#### Acceptance Criteria Met

- ✅ Global ORDER BY + LIMIT across 3 shards returns stable pagination
- ✅ Page boundaries have no overlap and are repeatable after reshuffle
- ✅ Shard failure returns well-typed error; retry after recovery succeeds
- ✅ EXPLAIN shows distributed plan with merge nodes

### 2. S3 Cloud Backups (Full + Incremental)

**Status**: ✅ IMPLEMENTED | **CLI**: `geode backup --dest s3://bucket/prefix`

#### Implementation

- **Multipart Uploads**: With checksums for files > 5MB
- **Incremental Chains**: Full backup + multiple incrementals with parent tracking
- **Resumable Uploads**: Exponential backoff with jitter on failures
- **Point-in-Time Recovery**: Reassembles full + incrementals, then applies WAL

#### Key Components

- `src/storage/s3_backup.zig`: S3 backup manager with multipart support
- Raft snapshots used as consistency anchors
- Non-intrusive read-only snapshots with throttled I/O

#### Acceptance Criteria Met

- ✅ Full + 3 incrementals restore to exact snapshot
- ✅ Checksums verified on all operations
- ✅ WAL replay < 60s for 10GB dataset
- ✅ Resumable uploads with retry logic

### 3. CDC Webhook Sink Hardening

**Status**: ✅ IMPLEMENTED | **Features**: Custom headers, retries, DLQ

#### Implementation

- **Custom HTTP Headers**: For auth tokens and routing
- **Retry Logic**: Exponential backoff with jitter (configurable)
- **Idempotency Keys**: Prevent duplicate deliveries
- **Dead Letter Queue**: With metrics and configurable retention

#### Key Components

- `src/cdc/webhook_sink.zig`: Enhanced webhook sink with reliability features
- At-least-once delivery guarantee with idempotency support
- Batch delivery with configurable size/timeout

#### Acceptance Criteria Met

- ✅ Custom headers observed at sink
- ✅ Retries with proper backoff on 502 errors
- ✅ Idempotency prevents duplicates
- ✅ Failed events land in DLQ with recovery support

### 4. CBO Calibration for Small-N

**Status**: ✅ IMPLEMENTED | Always enabled (legacy GEODE_ENABLE_CBO flag removed)

#### Implementation

- **Bias Corrections**: Adjusted factors for datasets < 100 rows
- **Guardrails**: Prevent > 10% regression vs heuristic planner
- **Decision Logging**: Under trace flag `GEODE_TRACE_OPTIMIZER=1`
- **Rich EXPLAIN**: JSON with estimates and confidence scores

#### Key Components

- `src/planner/cbo_small_n.zig`: Small-N calibration logic
- Confidence scoring based on statistics quality
- Validation against heuristic plans

#### Acceptance Criteria Met

- ✅ CBO matches or outperforms heuristic for micro-tables
- ✅ No test shows > 10% p95 regression
- ✅ Runtime toggle via environment variable
- ✅ EXPLAIN includes calibration details

## Known Limitations

### Federation

- Write path federation not implemented (reads only)
- No cross-shard transactions yet
- Global secondary indexes not supported

### S3 Backups

- Maximum file size: 100GB per backup
- S3-compatible APIs only (no native Azure/GCS)
- No encryption at rest (planned for v0.19)

### CDC

- Maximum batch size: 10,000 events
- DLQ not persistent across restarts
- No built-in schema evolution handling

### CBO

- Limited to single-node optimization
- No histogram support for custom types
- Trace logging can impact performance
