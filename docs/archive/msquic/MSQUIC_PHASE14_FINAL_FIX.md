## What Was Fixed

### 1. Double-Free Bug in QuicStream.write()

**Issue**: The `write()` function was experiencing a double-free error:
- Buffers were added to tracking lists before calling `StreamSend()`
- If `StreamSend()` failed, the error path would try to remove from tracking AND free
- The `errdefer` would then try to free again

**Root Cause**:
```zig
// BEFORE (buggy):
const data_copy = try self.allocator.dupe(u8, data);
errdefer self.allocator.free(data_copy);  // ← errdefer set

// Track buffers BEFORE send
self.context.mutex.lock();
try self.context.send_buffers.append(data_copy);
try self.context.send_buffer_structs.append(buffer_struct);
self.context.mutex.unlock();

const status = self.api.StreamSend(...);

if (msquic.QUIC_FAILED(status)) {
    // Manual cleanup - remove from tracking and free
    self.allocator.free(data_copy);  // ← First free
    return QuicError.StreamFailed;
    // errdefer fires here ← Second free (DOUBLE FREE!)
}
```

**Fix**: Track buffers AFTER successful send:
```zig
// AFTER (fixed):
const data_copy = try self.allocator.dupe(u8, data);
errdefer self.allocator.free(data_copy);  // ← errdefer set

const status = self.api.StreamSend(...);

if (msquic.QUIC_FAILED(status)) {
    // Send failed, let errdefer handle cleanup
    return QuicError.StreamFailed;
    // errdefer fires here ← Single free, correct!
}

// Send successful, NOW track buffers for async cleanup
self.context.mutex.lock();
self.context.send_buffers.append(data_copy) catch {};
self.context.send_buffer_structs.append(buffer_struct) catch {};
self.context.mutex.unlock();
```

**Evidence**: Server no longer crashes with "Invalid free" errors

### 2. Build System Fix

**Issue**: The build was failing with:
```
error: expected function or variable declaration after pub
pub usingnamespace @import("quic_msquic.zig");
```

**Fix**: Replaced `pub usingnamespace` with explicit re-exports:
```zig
// src/transport/quic.zig
const quic_msquic = @import("quic_msquic.zig");

pub const QuicError = quic_msquic.QuicError;
pub const QuicTransport = quic_msquic.QuicTransport;
pub const QuicConnection = quic_msquic.QuicConnection;
pub const QuicStream = quic_msquic.QuicStream;
pub const QuicClient = quic_msquic.QuicClient;
pub const QuicClientStream = quic_msquic.QuicClientStream;
```

This is a **client update issue**, not a server bug. The msquic migration is complete and working correctly.
