# lib:fts-storage

## summary

fts-storage is a pure-Zig (0.16.0+), zero-external-dependency, single-tenant, append-only inverted-index full-text-search STORAGE engine. It is a storage/indexing layer, NOT a query language: the caller tokenizes text into terms + token positions and hands them in; the engine never sees raw text. Token positions (not byte offsets) are the unit BM25 scores against and phrase queries align on; the library deliberately stores no byte offsets, so highlighting is a documented caller responsibility (re-tokenize the original doc to map positions->byte ranges).\n\nMODULE / IMPORT NAME: build.zig declares `b.addModule(\"fts_storage\", .{ .root_source_file = b.path(\"src/root.zig\") })`. Consumers write `const fts = @import(\"fts_storage\");`. build.zig.zon: name `.fts_storage`, version 0.1.0, min Zig 0.16.0, `.dependencies = .{}` (stdlib-only, self-contained). A static lib artifact `fts-storage` and a CLI exe `fts-storage` (from src/main.zig, suppressible via `-Dno-cli`) are also built. The bench framework is a second module `addModule(\"framework\", benchmarks/framework.zig)` (`@import(\"framework\")`), library-agnostic and copy-portable. PhraseIterator and AuthFilter are reached via `fts.search.*`.\n\nLIFECYCLE / ALLOCATOR / IO: `Engine.init(io: std.Io, allocator: std.mem.Allocator, base_dir: std.Io.Dir) !*Engine` (delegates to initWithConfig with defaults). `Engine.initWithConfig(io, allocator, base_dir, config: EngineConfig) !*Engine`. `Engine.deinit(self: *Engine) void`. Engine is HEAP-allocated (returns *Engine; deinit calls allocator.destroy(self)). The allocator is stored and used for ALL engine allocations. std.Io is Zig 0.16's IO interface; tests/examples/CLI use `std.Io.Threaded.global_single_threaded.io()`. CALLER retains ownership of base_dir and MUST close it AFTER engine.deinit; the engine opens/closes only the wal/ and segments/ subdirs (created at 0o700, files at 0o600). On init: validates aead_key length (must be 32 or error.InvalidKey), creates wal/ + segments/, loads A/B manifest (HMAC mismatch on either slot -> error.HmacMismatch fail-loud; both slots corrupt -> error.ManifestCorrupt; one corrupt slot falls back to the other), opens every segment (a corrupt segment is QUARANTINED to seg_N.corrupt and skipped ONLY when aead_key is set — without a key a load failure fails loud to avoid mistaking a forgotten key for corruption), replays the WAL, and builds engine-wide aggregated all_tombstones and all_norms maps for O(1) lookup.\n\nCONFIG/DEFAULTS: `EngineConfig{ hmac_key: ?[]const u8 = null, aead_key: ?[]const u8 = null }`. hmac_key (any length; tests use 32-byte strings) appends a trailing 32-byte HMAC-SHA256 envelope over (record||crc) on every WAL record and on the manifest; a mismatch is never silently masked. aead_key (exactly 32 bytes) enables AES-256-GCM at-rest encryption of all four segment files (terms.hash, postings.bin, norms.bin, tombstones.bin) with per-file random 12-byte nonce + 16-byte tag (28-byte overhead; nonce||ct||tag wire format). Both default null = byte-for-byte legacy plaintext. There is NO runtime knob for BM25 params or the memtable flush threshold — those are compile-time constants.\n\nINDEXING (all assert single-thread ownership in debug + take the engine WRITE lock): `Engine.indexDocument(doc_id: u64, terms: []const TermPosting) !void` (validate -> WAL BEGIN/index_doc/COMMIT+fsync durable-first -> mutate memtable -> auto-flush at threshold); `Engine.indexDocumentBatch(docs: []const DocBatch) !void` (validate ALL up front, append every record with NO intervening fsync, ONE trailing fsync, then mutate memtable — empty batch is a no-op, an invalid doc rejects the WHOLE batch consuming zero txn_ids); `Engine.indexDocumentExcluding(doc_id, terms, excluded_fields: []const []const u8) !void` (FLE guard: error.FieldExcluded before any side effect if any TermPosting.field matches; null-field postings bypass the check). `Engine.deleteDocument(doc_id: u64) !void` (tombstone; mirrored into all_tombstones; WAL BEGIN/delete_doc/COMMIT+fsync; visible after reopen via WAL replay even without flush). Boundary validation: error.EmptyTerm, error.TermTooLong (>16 KiB), error.PositionCountTooLarge (>1,048,576), error.PositionsNotMonotonic (positions must be ascending). Auto-flush fires when memtable distinct-doc count >= 65536.\n\nFLUSH/COMPACT: `Engine.flush() !void` seals the memtable into a new immutable on-disk segment (seg_<counter+1>) and durably A/B-rotates the manifest — 3 phases with errdefer rollback: (1) write segment, (2) durably write manifest [point of no return], (3) truncate WAL + open SegmentReader; updates total_docs, length-weighted avg_doc_len, counter, last_checkpoint_lsn; no-op on empty memtable. `Engine.flushAsync() !void` + `Engine.flushWait() !void`: flushAsync drains any prior worker then spawns a std.Thread running flushWorker (which takes the write lock and runs flushLocked, capturing any error into pending_flush_err); flushWait joins and returns the captured error (no-op if none); deinit auto-joins. Note: flushAsync deadlocks under the single-threaded test IO, so it requires a multi-threaded std.Io. `Engine.compact() !void` (no-op if <=2 segments): merges every segment's postings into one fresh memtable, EXCLUDING any doc in all_tombstones, writes it as a level=1 segment, durably rotates the manifest, deletes old segment dirs best-effort, then clears all_tombstones (now baked in by exclusion) and rebuilds all_norms.\n\nQUERY (src/search.zig): `TermIterator.init(allocator, eng: *Engine, term) !TermIterator`; `TermIterator.initWithAuth(allocator, eng, term, auth_filter: ?AuthFilter, auth_ctx: ?*anyopaque) !TermIterator`; `.next() !?Match`; `.deinit()`. `Match{ doc_id: u64, positions: []const u32 (ascending token positions, borrowed — valid until next()/deinit()), score: f32 (BM25; 0.0 valid) }`. `AuthFilter = *const fn(doc_id: u64, ctx: ?*anyopaque) bool` is a caller RLS/ABAC POST-filter applied AFTER tombstone gating (so an unauthorized-but-deleted doc reads as deleted — keeps timing side-channel identical). The iterator holds the engine rw-lock SHARED for its whole lifetime: any number of reader threads may iterate concurrently, but WRITERS BLOCK while any iterator is alive (coarse but correct for v0.1; RCU snapshot deferred). next() yields memtable matches first then segment matches, skipping tombstoned/unauthorized docs. `PhraseIterator.init(allocator, eng, terms: []const []const u8, slop: u32) !PhraseIterator` + `.initWithAuth(...)` + `.next() !?TermIterator.Match` + `.deinit()` — positional phrase matching (slop=0 = adjacent, slop>0 = window); minimum-viable O(N*M*P) impl that re-iterates trailing terms per candidate. BM25 constants are fixed: `BM25_K1: f32 = 1.2`, `BM25_B: f32 = 0.75`; standard Robertson/Sparck-Jones idf*tf_norm with length normalization; falls back to DEFAULT_DOC_LEN=100 when corpus stats are missing (pre-first-flush or memtable doc); empty corpus (N=0) -> score 0.0. There is NO built-in boolean AND/OR/NOT combinator — boolean intersection is a caller responsibility (PostingIterator.nextDocOnly exists to make it cheap).\n\nPERSISTENCE MODEL: file-backed LSM, NOT in-memory and NOT mmap. (1) Append-only WAL (wal/fts.wal) of CRC32C-checked records; each index/delete is bracketed BEGIN/payload/COMMIT sharing a txn_id and fsync'd once; 3-pass replay applies only txns past the checkpoint LSN whose COMMIT was observed — a crash mid-bracket rolls back (verified: 'WAL replay drops uncommitted records', 'tolerates truncated WAL tail'). (2) Immutable LSM segments (segments/seg_N/{terms.hash, postings.bin, norms.bin, tombstones.bin}) with delta-encoded doc_ids + LEB128 varint postings/positions. (3) A/B atomic manifest (manifest.a/manifest.b, magic FTSMNF01, format_version 2) selected by highest monotonic counter, persisted via atomicWrite (random-suffixed temp + O_EXCL + fsync + rename; no parent-dir fsync since Zig 0.16 lacks it — WAL is the durability source of truth). Reads pass follow_symlinks=false; created paths can still be symlink-followed (documented; mitigated by 0o700 dirs and caller securing base_dir). Aggregate WAL-replay buffer is capped at 10 GiB (error.WalTooLarge).\n\nCONCURRENCY MODEL: SINGLE-WRITER, MULTI-READER, single-tenant. Writes are single-threaded BY CONTRACT — owning thread captured at init, every mutating method debug-asserts the caller is on it (compiled out in release via std.debug.runtime_safety; a violation in release is silent UB). An engine-wide std.Io.RwLock gives writers exclusive and readers shared access. next_txn_id is std.atomic.Value(u64) bumped with monotonic fetchAdd. No internal write serialization — callers must serialize their own writes on the owning thread.\n\nERROR SET (src/errors.zig — four named sets re-exported per module as `pub const Error` so consumers can switch exhaustively): EngineError = {EmptyTerm, TermTooLong, PositionCountTooLarge, PositionsNotMonotonic, ManifestCorrupt, ManifestTooLarge, HmacMismatch, InvalidKey, CiphertextTooShort, FieldExcluded, WalTooLarge}. WalError = {InvalidData, InvalidMagic, ChecksumMismatch, Incomplete, PayloadTooLarge, Overflow}. ManifestError = {InvalidData, InvalidMagic, ChecksumMismatch, ManifestTooLarge, SegmentCountTooLarge, NoManifest}. SegmentError = {InvalidData, InvalidMagic, ChecksumMismatch, TermCountTooLarge, TombstoneCountTooLarge, NormCountTooLarge, PostingsTooLarge, PositionCountTooLarge, PositionOutOfRange}.\n\nSERIALIZATION/SNAPSHOT APIs (public, for tooling/fuzzing): Manifest.serialize/serializeWithHmac/deserialize/deserializeWithHmac/writeToFile/writeToFileWithHmac/selectManifest; WalRecord.serialize/serializeInto/deserialize; WalWriter.append/sync/appendAndSync; WalReader.next; SegmentWriter.writeMemtable; SegmentReader.init/initWithAead/search/deinit; PostingIterator.next/nextDocOnly; Memtable.init/deinit/addPosting/addTombstone; utils.writeVarInt/readVarInt (inline LEB128, overflow-checked), hashCrc32c, aeadEncrypt/aeadDecrypt + AEAD_*length consts, atomicWrite, writeU{16,32,64}Le/readU{16,32,64}Le/readU32LeAt, fileMode/dirMode. There is no single 'snapshot the whole engine' call; durability IS the segment+manifest pair produced by flush.\n\nBENCHMARK (benchmarks/bench.zig, run `zig build bench [-- --output bench.json | --filter X | --list | --warmup N | --samples N | --no-track | --quiet]`; forced ReleaseFast for both the bench lib copy and framework so numbers are comparable regardless of -Doptimize): 9 scenarios driving the real Engine, measuring wall-time percentiles (p50/p95/p99/min/max/stddev) and throughput ops/sec via the framework. Scenarios: engine_init_cycle (16 init/deinit), engine_index_document (1000 single-term docs, 1 fsync/doc — the ~186 docs/s baseline), engine_index_document_batch64 (same workload via 64-doc batches — the group-commit comparison, ~12,800 docs/s ceiling, ~69x), ingest_100k_docs_random_terms (50k vocab, 8 terms/doc), flush_100k_term_memtable (op_count=1 so wall_ns_p50 == flush latency), replay_wal_1M_records (3-pass replay), query_term_iterator_16_segments (16 segments x 10k docs, TermIterator fan-out), posting_iter_next_with_positions and posting_iter_next_doc_only (10k-entry paired micro showing the nextDocOnly position-skip win). ## perf_notes

Benchmarks force ReleaseFast for both the bench copy of the library and the framework module regardless of -Doptimize (WRK-024/PERF-0020/PERF-0025) so `zig build bench` numbers are comparable. Framework defaults: warmup_iterations=3, sample_iterations=30; reports min/p50/p95/p99/max + mean-based throughput stddev; tracks alloc count/bytes/peak via TrackingAllocator (disable with --no-track); RSS from /proc/self/status on Linux only (0 elsewhere). Stated targets/baselines: per-record fsync indexing ceiling ~186 docs/s (engine_index_document, 1 fsync/doc, znver2/linux/ext4 @ HEAD 9159059); 64-doc group-commit ceiling ~12,800 docs/s (~69x, engine_index_document_batch64); BM25 per-doc length lookup via the engine-wide aggregated all_norms map ~19.5 MOPS at 16 segments vs ~2.2 GOPS for the single-segment closed form (the O(segments) scan was 'the wrong shape for any non-toy query path'); PostingIterator.nextDocOnly skips the position varint loop (~half the per-posting wall time at large fan-out). flush_100k_term_memtable uses op_count=1 so wall_ns_p50 == flush latency. compare-bench (`zig build compare-bench -- a.json b.json`) diffs two result files and gates regressions against benchmarks/results/baseline.json. CRC32C is table-driven (~1.2 GiB/s, no HW dispatch in Zig 0.16) but dominated by surrounding IO.

## risks

- v0.1 concurrency is coarse: a live TermIterator/PhraseIterator holds the engine rw-lock SHARED, so ANY writer blocks for the iterator's entire lifetime. Long-running queries stall indexing — drain/close iterators promptly and batch results.
- Single-writer-by-contract: mutating methods debug-assert the owning thread, but those asserts are COMPILED OUT in release (std.debug.runtime_safety) — a multi-thread-write bug becomes silent UB in release. Callers MUST serialize all writes on the init thread themselves.
- Caller owns tokenization AND highlighting: the engine stores token positions, not byte offsets; symmetric tokenization at index and query time is required, and byte-offset highlight mapping is entirely the consumer's job.
- Corrupt-segment quarantine on init happens ONLY when aead_key is set; without AEAD a segment load failure fails loud (to avoid mistaking a forgotten key for corruption). Operators relying on restart-resilience must understand this branch.
- BM25 params (k1=1.2/b=0.75) and the memtable auto-flush threshold (65536 docs) are compile-time constants — not tunable at runtime in v0.1.
- No built-in boolean (AND/OR/NOT) query combinator — multi-term boolean logic is a caller responsibility built on TermIterator/PostingIterator.nextDocOnly.
- flushAsync deadlocks under the single-threaded std.Io used by unit tests/CLI; it requires a multi-threaded event loop, so its end-to-end path is exercised only by integration tests that configure one.
- Created (not-yet-existing) paths can be symlink-followed since Zig 0.16 lacks O_NOFOLLOW on create; mitigated by 0o700 dirs but the parent base_dir is the caller's security responsibility.
