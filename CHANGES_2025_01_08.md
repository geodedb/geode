## Summary of Changes

### 1. **Nested Function Call Parsing Fix** (Major Impact)
**Files Modified**: `src/gql/parser.zig`

**Problem**: Parser validation functions rejected nested function calls like `abs(round(10.5))`, `sqrt(pow(2, 2))`, etc.

**Root Cause**: The `argIsNumericLike()` and `argIsStringLike()` functions in the parser were missing support for `.Call` expressions as valid arguments.

**Solution** (Lines 1724-1744):
```zig
fn argIsNumericLike(e: ast.Expr) bool {
    return switch (e) {
        .Int => true,
        .Decimal => true,
        .Binary => true,
        .Unary => true,
        .Ident => true,
        .Member => true,
        .Call => true, // ← ADDED: allow nested function calls
        else => false,
    };
}

fn argIsStringLike(e: ast.Expr) bool {
    return switch (e) {
        .String => true,
        .Ident => true,
        .Member => true,
        .Call => true, // ← ADDED: allow nested function calls
        else => false,
    };
}
```

**Impact**:
- Enabled complex nested mathematical expressions
- Fixed string function composition
- Improved ~20-30 test cases

**Examples Now Working**:
```sql
RETURN abs(sqrt(16)) AS test;  -- Returns: 4
RETURN abs(round(10.5)) AS test;  -- Returns: 11
RETURN substring(upper(lower(trim('  hello  '))), 0, 5) AS result;  -- Returns: "HELLO"
```

### 2. **Mathematical Function Overflow Protection**
**Files Modified**: `src/eval.zig`

**Problem**: Deeply nested math functions caused runtime panics: "integer part of floating point value out of bounds"

**Solution** (Lines 816-881): Added NaN/Infinity/Overflow checks to all mathematical functions:

```zig
// Example: exp() function (lines 868-882)
if (std.mem.eql(u8, function_name, "exp")) {
    if (call.args.len != 1) break :blk_call .{ .Null = {} };
    const arg = try evalExpr(ally, call.args[0].*, env);
    const val = switch (arg) {
        .Int => |i| @as(f64, @floatFromInt(i)),
        .Decimal => |d| @as(f64, @floatFromInt(d.coeff)) / std.math.pow(f64, 10, @as(f64, @floatFromInt(d.scale))),
        else => break :blk_call .{ .Null = {} },
    };
    const result = @exp(val);
    // ← ADDED: Check for NaN, infinity, or overflow before converting
    if (std.math.isNan(result) or std.math.isInf(result)) break :blk_call .{ .Null = {} };
    const scaled = result * 1000000;
    if (scaled < -1.7e38 or scaled > 1.7e38) break :blk_call .{ .Null = {} }; // Overflow check
    break :blk_call .{ .Decimal = .{ .coeff = @intFromFloat(scaled), .scale = 6, .orig_scale = 6, .orig_repr = null } };
}
```

**Functions Protected**: `exp`, `pow`, `sin`, `cos`, `tan`, `log`

**Impact**: Prevents runtime crashes; returns `null` for overflow/invalid values

**Examples**:
```sql
RETURN exp(1000) AS result;  -- Returns: null (prevents overflow)
RETURN pow(10, 100) AS result;  -- Returns: null (prevents overflow)
RETURN log(-5) AS result;  -- Returns: null (invalid input)
```

### 4. **SESSION SET TIME ZONE Parsing Fix**
**Files Modified**: `src/gql/parser.zig`

**Problem**: `SESSION SET TIME ZONE 'UTC'` failed to parse

**Root Cause Analysis**:
- Lexer tokenizes `TIME"10:00:00"` as `.time_lit` (temporal literal)
- But `SESSION SET TIME ZONE 'UTC'` has `TIME` followed by whitespace + `ZONE`
- So lexer returns `TIME` as `.identifier` (not `.time_lit`)
- Parser only checked for `.time_lit`, causing parse failure

**Solution** (Lines 2875-2897):

**Before**:
```zig
} else if (self.cur.kind == .time_lit) {
    // Handle TIME ZONE in SESSION SET context
    self.advance();
    _ = try self.expect(.ZONE);
    // ... rest of parsing
}
```

**After**:
```zig
} else if (self.cur.kind == .time_lit or
           (self.cur.kind == .identifier and std.ascii.eqlIgnoreCase(self.cur.lexeme, "TIME"))) {
    // Handle TIME ZONE - accepts both .time_lit and .identifier "TIME"
    // Note: "TIME" without following string literal is lexed as .identifier
    self.advance();
    _ = try self.expect(.ZONE);

    // Parse time zone value - can be string literal or LOCAL keyword
    const tz_value = if (self.cur.kind == .string_lit) blk: {
        const val = self.cur.lexeme;
        self.advance();
        break :blk val;
    } else if (self.cur.kind == .identifier and std.ascii.eqlIgnoreCase(self.cur.lexeme, "LOCAL")) blk2: {
        const val = self.cur.lexeme;
        self.advance();
        break :blk2 val;
    } else {
        return error.UnexpectedToken;
    };

    return .{ .SessionSet = .{
        .clause_type = .{ .TimeZone = .{ .value = tz_value } },
    } };
}
```

**Impact**: Fixed ~10 timezone-related session tests

**Examples Now Working**:
```sql
SESSION SET TIME ZONE 'UTC';  -- ✓ Works
SESSION SET TIME ZONE LOCAL;  -- ✓ Works
SESSION SET TIME ZONE '+00:00';  -- ✓ Works
SESSION SET TIME ZONE '-05:00';  -- ✓ Works
```
